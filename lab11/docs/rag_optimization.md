# Результат 5. Контрольована оптимізація «до/після»

- **Гіпотеза:** збільшення `top_k` з 3 до 5, підвищення порогу відмови з 0.40 до 0.58 та увімкнення guard проти prompt injection підвищать `context_recall`, `abstention_rate` і безпеку.
- **Порівняння до/після (32 тести):**

| Метрика | До (`k=3, t=0.40, guard=off`) | Після (`k=5, t=0.58, guard=on`) | Зміна |
| :--- | :---: | :---: | :---: |
| **Faithfulness** | 0.906 | 0.844 | -0.062 |
| **Context Recall** | 0.875 | 0.938 | **+0.063** |
| **Citation Accuracy** | 1.0 | 1.0 | 0.000 |
| **Abstention Rate** | 0.917 | 1.0 | **+0.083** |
| **Injection Block Rate** | 0.75 | 1.0 | **+0.250** |
| **Затримка p50 / p95 (мс)** | 0.42 / 0.567 | 0.442 / 0.581 | +0.022 / +0.014 мс |
| **Середні токени / запит** | 331.1 | 384.6 | +53.5 токенів |
| **Оцінна вартість / 1000 запитів** | $0.0662 | $0.0769 | +$0.0107 |

- **Висновок:** зміна `top_k=5` + `injection_guard=True` повністю окуповується (+6.3% context recall, +25% блокування ін’єкцій за мізерні +0.014 мс p95 та +$0.01/1k запитів), однак поріг `0.58` виявився зависоким і знизив `faithfulness` (-6.2%) через хибні відмови — у продакшн рекомендовано залишити `top_k=5`, `guard=on` та відкалібрований поріг `0.42`.
