# Результат 1. Дизайн рекомендаційного модуля

## Архітектура та підходи
1. **Popularity Baseline** — частотне ранжування за train-взаємодіями (тижні 1–12).
2. **Graph-Path Recommender (`graph`)** — 2- та 3-крокові шляхи у графі знань (`User -> Item_hist -> KG_Entity -> Candidate`) із вагами `freq / log2(deg + 1.5)`.
3. **Embeddings kNN (`embeddings`)** — косинусна подібність між профілем користувача (середній вектор переглянутих документів) та 18-вимірними семантичними ембедингами документів.
4. **Гібридне ранжування**:
   - `hybrid_weighted`: `0.45 * norm(graph) + 0.55 * norm(embeddings)`.
   - `hybrid_rrf`: `1/(60 + rank_graph) + 1/(60 + rank_emb) + 0.15/(60 + rank_pop)`.

## Фільтри якості та прав доступу (демо на 34 елементах)
- `guest`: допущено **4** (вилучено: 4 неперевірених, 2 застарілих >180 дн., 24 RBAC).
- `coach`: допущено **25** (вилучено: 4 неперевірених, 2 застарілих, 3 `restricted`).
- `doctor`: допущено **28** (вилучено: 4 неперевірених, 2 застарілих, 0 RBAC).

## Обмеження (4)
1. Залежність графового підходу від повноти зв’язування сутностей (Entity Linking з ЛР №13).
2. Синтетичні 18-вимірні ембединги у тестовому середовищі не замінюють повнорозмірні багатомовні трансформери в продакшені.
3. Відсутність онлайн A/B-тестування (CTR, dwell time) на реальному трафіку клубу.
4. Статичне вікно свіжості 180 днів може приховувати базові довідкові регламенти, що оновлюються раз на рік.
